Log levels:
DEBUG - developer details
INFO - pipeline progress
WARNING - something odd/strange
ERROR - task failed
CRITICAL - system failure

Debugging Python code:
last line of the error message -> error type
lines above the last line of the error message -> call path of the error
defensive fixes - make functions raise their own errors instead of waiting for Python to do it

Python to Snowflake flow:
Python code -> Snowflake driver -> Snowflake engine -> Tables (in Snowflake)

Using APIs with Python:
REST basics:
types of requests:
GET - fetch data
POST - send data
PUT/PATCH - update data
DELETE - remove data

Note: accessing APIs does have limitations (dependent on the API) on requests/rates
read the API's website for details on those limitations
example of real API with live data - finhub (live stock data)

Pagination when retrieving data from APIs:
partitions the fetching of the data so that it can be fetched in chunks
instead of all at once since doing it all at once could crash the system
due to the resource load. It also helps with APIs that contain large amounts of data.

API retry logic (related to APIs' request limitations):
HTTP codes:
200-299 -> successful
400 - 499 -> failed

Object Oriented Programming (OOP) in Python:
use it to reduce complexity, not create it
not applicable to every situation, so need to be careful when/where it gets used
be mindful of efficiency
if there is a need for shared state, shared context, or shared configuration then OOP might be useful
a class works like a container for functions with shared state/context/configuration

Class structure for a data pipeline:
DataPipeline
    extract_data() - extract task
    transform_data() - transform task
    load_data() - load task
    run() - used to orchestrate the extract, transform, & load tasks

Performance optimization in Python:
Python itself is slow, so optimization via how programs are written is necessary
Using packages to work on things is way more efficient, if chosen correctly
Badly formed loops, unnecessary memory usage, doing tasks in Python that
you're not meant to do in Python
Don't load in files that you don't need
Copying dataframes & holding dataframes (which are in memory) for longer than needed
are also not good
Data saved in variables & data structures are in memory during Python code runtime,
so having data too large in size/count will slow down the system
Hold data only when it's necessary - matters less with small datasets,
but with industry/production huge datasets, it changes a lot
Use vectorized methods (Pandas, which uses C under the hood) instead of loops (matters less for small data, but is huge for larger datasets)
For example, don't loop through data that can be converted into a table format (for example, Pandas dataframes)

Concurrency in Python:
Multithreading in Python:
One process at a time
Shared memory
GIL (global interpreter lock) bottleneck - can only perform 1 Python task at a time

Multiprocessing in Python:
Multiple processes at a time
Separate memory
True parallelism

Rather than just using Python alone to transform data, use other tools like PySpark
to do distributed & parallel computing while Python is just there to orchestrate

Managing secrets/keys in real-world & production projects:
Use environment variables to hide secrets/keys from those who read Python code,
instead of hard-coding these secrets/keys/credentials into the code
